# Sift Gate

[Документация проекта](https://olluorg.github.io/sift-gate/) · [Провайдеры](https://olluorg.github.io/sift-gate/providers/) · [Цены моделей](https://olluorg.github.io/sift-gate/models/)

Асинхронная Rust-библиотека для маршрутизации LLM-запросов между OpenRouter, RouterAI, Polza.ai и подключаемыми провайдерами. Точки входа `chat_completions` и `messages` принимают JSON в форматах OpenAI Chat Completions и Anthropic Messages. Библиотека подставляет ID модели из маршрута и передаёт остальные поля, включая tools, tool results и изображения на входе. Поддержка конкретного поля зависит от выбранных модели и провайдера.

## Подключение

Для ProxyAPI и AITUNNEL используйте [пример с российскими провайдерами](sift-gate.ru.example.toml). Оба маршрута поддерживают Chat Completions и Anthropic Messages. Встроенный `ai_tunnel` загружает рублёвые цены из публичного каталога AITUNNEL. ProxyAPI подключается через `compatible`. Его документированный список моделей не содержит ставок, поэтому библиотека оставляет цену маршрута неизвестной.

Добавьте `sift-gate` как path-зависимость, скопируйте [пример TOML](sift-gate.example.toml) в `sift-gate.toml` и установите переменные окружения для настроенных провайдеров. Проверьте ID моделей в каталогах и укажите курс `rub_per_usd`, если сравниваете рублёвые цены с долларовыми. Конфиг явно перечисляет маршруты для каждого алиаса и протоколы, доступные на каждом маршруте.

~~~rust
use futures_util::StreamExt;
use serde_json::json;
use sift_gate::{Config, Error, ProviderResponse, SiftGate};

async fn ask() -> Result<(), Error> {
    let gate = SiftGate::new(Config::from_file("sift-gate.toml")?)?;
    let result = gate.messages(json!({
        "model": "claude",
        "max_tokens": 256,
        "stream": true,
        "messages": [{"role": "user", "content": "Привет!"}]
    })).await?;

    println!("{} / {}", result.provider, result.model);
    match result.response {
        ProviderResponse::Json(body) => println!("{body}"),
        ProviderResponse::Stream(mut events) => {
            while let Some(event) = events.next().await {
                let event = event?;
                println!("{:?} {}", event.event, event.data);
            }
        }
    }
    Ok(())
}
~~~

Запускайте вызов внутри Tokio. Для OpenAI используйте `gate.chat_completions(body)`. Установите `"stream": false` или опустите поле для обычного JSON-ответа. Поток содержит распарсенные SSE-события с полями `event` и `data`, включая терминальное событие. Переиспользуйте экземпляр `SiftGate` между запросами. Его клоны разделяют кэш цен, circuit breaker и EWMA в памяти процесса.

## Стратегии

- `LowestLatency` использует EWMA по TTFT для SSE и по полной задержке для обычных ответов. Маршруты без замеров получают возможность набрать статистику.
- `LowestCost` сортирует маршруты по расчётной стоимости запроса. Маршруты без сопоставимой цены идут после маршрутов с ценой.
- `Balanced` нормализует оценки задержки и цены в диапазоне от 0 до 1 и смешивает их с весом `latency_weight` для задержки. Неизвестная задержка получает 0,5, неизвестная цена получает 1. При равном балле действует порядок из TOML.

Цены загружаются из каталогов по мере запросов и обновляются по `catalog_ttl_ms`. При сбое обновления сохраняется последний успешный снимок. Входные токены оцениваются по размеру JSON, выходные — по `max_completion_tokens` или `max_tokens` с запасным значением 512. Оценка приблизительная, особенно для медиа, кэширования и запросов со специальной тарификацией. При смешении USD и RUB используется USD. Без курса рублёвая цена в смешанном наборе считается неизвестной. Для набора в одной валюте курс не нужен.

## Телеметрия и failover

TTFT измеряется до первого содержательного события с текстом, рассуждением или вызовом инструмента. Для стриминга замеры отражают время чтения событий потребителем. Полная задержка записывается после успешного JSON-ответа или терминального SSE-события. `gate.telemetry(provider, model, protocol)` возвращает сглаженные значения по конкретному маршруту.

При 429, 5xx, таймауте или сбое транспорта/протокола circuit breaker изолирует провайдера на `cooldown_ms`. После cooldown один реальный запрос может проверить его восстановление. При SSE переключение возможно до выдачи первого события. Обрыв после этого возвращается как ошибка потока. `timeout_ms` применяется к каждой попытке и включает чтение ответа. По умолчанию повтор после таймаута разрешён и может привести к повторной оплате. Чтобы отключить такие повторы, задайте `retry_timeouts = false`.

## Расширения

- `ProviderAdapter` позволяет реализовать собственный транспорт, формат и авторизацию. Зарегистрируйте адаптер под именем провайдера с `kind = "custom"` через `SiftGate::with_extensions`. Для стандартного OpenAI-совместимого сервиса можно использовать `kind = "compatible"` с `base_url`, `api_key_env` и валютой каталога.
- `ScoringPolicy` получает исходный JSON, режим стриминга, телеметрию и оценку цены каждого доступного маршрута. Меньший балл означает более высокий приоритет.

Первая версия охватывает текстовые LLM-запросы, инструменты и изображения во входном контенте. Отдельные API для OpenAI Responses, генерации изображений и видео, распознавания и синтеза речи — следующие этапы.

`cargo test` запускает сценарии без ключей и платных запросов.

## Сайт и каталог

`python scripts/build_catalog.py` собирает сайт в `site-dist/` из сохранённого снимка. С флагом `--refresh` сборка читает публичные каталоги и курс Банка России. Для локального просмотра запустите `python -m http.server --directory site-dist`. GitHub Actions обновляет и публикует сайт ежедневно. Источники и даты снимков отображаются в каталоге.

Реферальные ссылки задаются в поле `referral` файла [site/providers.json](site/providers.json) после получения ссылки в кабинете провайдера.

## Интеграционные HTTP-тесты

Один локальный мок-сервер имитирует OpenRouter, RouterAI, Polza.ai, ProxyAPI и AITUNNEL. Тесты проверяют авторизацию, JSON и SSE обоих протоколов, схемы каталогов и конвертацию цен, реакцию на 429, замедление провайдера, таймаут и обрыв стрима. Используются фиктивный ключ и синтетические ответы.

Быстрый запуск с Python 3.12 и Rust. Скрипт сам выбирает свободный локальный порт и останавливает моки после тестов.

~~~sh
python tests/http/mock.py
~~~

Те же тесты с Docker Compose.

~~~sh
docker compose -f tests/http/compose.yaml up -d --wait
python tests/http/mock.py --url http://127.0.0.1:18080
docker compose -f tests/http/compose.yaml down
~~~

Обычный `cargo test` запускает тесты, которые обходятся без HTTP-сервера. Для Cargo без доступа к реестру можно добавить `--offline` к команде запуска моков, если зависимости уже в кэше.
